# Feature map

Each user-visible feature, the committed examples that drive it, and what no example drives yet. Copy from them when you write the test that proves your change. An example's test names say what it drives; read the test for how.

| Feature | Behavior | Examples | Not covered |
| --- | --- | --- | --- |
| Open with the hotkey | Control-Option-Space (Control-Option-Command-Space in Aside Verify) opens the panel over the app in front, with the cursor in the field; that app stays active and typing goes into the panel. | [testHotkeyOpensPanelOverFrontApp](../../../../UITests/Tests/PanelTests.swift), through `pressHotkey` in [AppActions.swift](../../../../UITests/Support/AppActions.swift) | The default Control-Option-Space itself; which display it opens on; full-screen apps and other Spaces (manual) |
| Close the panel | Esc closes it; pressing the hotkey again closes it; clicking outside closes it. | [testHotkeyOpensPanelOverFrontApp](../../../../UITests/Tests/PanelTests.swift) (Esc), [testMenuBarOpensPanelAndHotkeyClosesIt](../../../../UITests/Tests/PanelTests.swift) (hotkey) | Click outside; typing going back to the previous app after closing, which XCUITest can't show (manual test 3) |
| Menu bar item | The speech-bubble icon's menu has Show Aside, which opens the panel, and Quit Aside. | [testMenuBarOpensPanelAndHotkeyClosesIt](../../../../UITests/Tests/PanelTests.swift), through `openPanelFromMenuBar` | Quit Aside |
| URL scheme | `aside://show`, `hide` and `toggle` open, close and toggle the panel (`aside-verify://` in Aside Verify). | Every test that uses `openPanelWithURL` (`show`); `openURL` in [AppActions.swift](../../../../UITests/Support/AppActions.swift) sends any action | `hide` and `toggle`; an unknown URL; LaunchServices routing of `aside://` |
| claude status line | The line under the field shows `claude: <path>`, or that claude was not found. | [testPanelShowsWhereClaudeIs](../../../../UITests/Tests/PanelTests.swift), [testMissingClaudeShowsInPanel](../../../../UITests/Tests/ConversationTests.swift) | |
| Ask and answer | Return sends the question and clears the field; the answer streams in under it, with "Thinking…" or "Searching the web…" until text arrives. Follow-ups go to the same claude. The transcript grows the panel downward, then scrolls. | [testAnswersFollowUpsAndNewConversation](../../../../UITests/Tests/ConversationTests.swift) (fake claude) | Real claude, web search and long answers have no committed example (they need the subscription); copy `launch()` and `CONTAINS` from Which claude in SKILL.md. Streaming pace (manual) |
| New conversation | Command-N or the New conversation button empties the panel and starts a fresh claude. Opening the panel more than 10 minutes after the last answer does the same. | [testAnswersFollowUpsAndNewConversation](../../../../UITests/Tests/ConversationTests.swift) (Command-N) | The button click; the idle reset (unit-tested) |
| claude failures | claude exiting shows "claude stopped (exit status N): …" and the next question starts over; a missing claude shows when asking. | [testClaudeStoppingShowsInPanel](../../../../UITests/Tests/ConversationTests.swift), [testMissingClaudeShowsInPanel](../../../../UITests/Tests/ConversationTests.swift) | A failed turn (`is_error` result) |
| Talk | Control-Option-Shift-Space (Control-Option-Shift-Command-Space in Aside Verify) opens the panel listening, or starts listening in the open panel after what was typed. Words show in the field as they're heard; pressing it again or Return sends. Esc throws the words away and closes; typing stops listening and keeps the text; closing otherwise keeps it unsent. Hearing nothing or failing to listen shows a red line under the field. | [VoiceTests](../../../../UITests/Tests/VoiceTests.swift): `testTalkHotkeyListensAndSecondPressSends`, `testEscThrowsAwayWhatWasHeard`, `testClosingKeepsWhatWasHeard`, `testTypingStopsListening`, `testListeningFailureShows` (all through `launch(heard:)`) | Hearing nothing (needs a silent clip; unit-tested). The microphone, its permission prompt, headsets (manual) |
| Read aloud | The answer to a question sent while listening is read aloud a sentence at a time, with "Reading aloud. Esc stops." under the field until it has been said. Typed questions aren't read. Esc, the talk hotkey, the next question and Command-N stop it; closing with the hotkey keeps reading. | [ReadAloudTests](../../../../UITests/Tests/ReadAloudTests.swift): `testSpokenQuestionIsReadAloud`, `testTypedQuestionIsNotReadAloud`, `testEscStopsReadingAndClosingDoesNot`, `testTalkingStopsReading` | The sound, which words are said (unit-tested), the next question and Command-N stopping it (unit-tested) |
| Edit shortcuts | Command-X, C, V, A and Z work in the field, through a hidden Edit menu. | None committed | Copying from the transcript (manual) |

## Keeping it current

A row changes when an example is added, moved into `UITests/Tests/`, or deleted, or when a feature appears or goes away.
